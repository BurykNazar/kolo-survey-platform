# Kolo — платформа онлайн-опитувань

**Демо:** https://kolo-survey-platform.onrender.com

Kolo збирає відповіді команд, клієнтів і громад в одному місці: каталог опитувань,
конструктор анкет, проходження після входу, автозбереження чернеток, журнал відповідей і рольовий кабінет.

Стек: **Express 5 · Nunjucks · Sequelize · PostgreSQL (Neon) · Render**.
Інтерфейс — українською, дизайн-система — власна (Unbounded + Onest, папір / ліс / лайм).

## Можливості

- Каталог активних опитувань із темами, пошуком і датою завершення.
- Конструктор: назва, опис, тема, статус, тривалість, дата завершення, анонімність,
  питання чотирьох типів (один варіант, кілька варіантів, текст, шкала 1–10).
- Проходження анкет після входу; автор може дозволити анонімність, учасник сам обирає,
  прикріплювати відповідь до профілю чи ні.
- Чернетка відповідей зберігається в PostgreSQL і відновлюється після перезавантаження;
  серверна валідація без HTML `required`, надсилання через AJAX.
- Журнал відповідей, згрупованих за спробами; перегляд анкети в бічній панелі.
- Ролі: адміністратор, дослідник, учасник — з різними правами на сторінках і в API.
- JWT REST API для шести сутностей (опитування, категорії, користувачі, питання,
  варіанти, результати).
- Сесії зберігаються в PostgreSQL, а не в пам’яті процесу.

## Швидкий старт

```powershell
npm install
Copy-Item .env.example .env
# заповніть DATABASE_URL, SESSION_SECRET, JWT_SECRET
npm run db:setup
npm run dev
```

`npm run db:setup` створює схему та наповнює її демонстраційними даними, якщо база
порожня. Паролі згенерованих акаунтів друкуються в консоль і записуються у
`credentials.local.md` (файл у `.gitignore`). Готовий список демо-акаунтів для живого
сайту — `DEMO-ACCESS.md`. Повторне створення з нуля:

```powershell
npm run db:reset
```

## Середовище

| Змінна | Призначення |
| --- | --- |
| `DATABASE_URL` | рядок підключення Neon Postgres, наприклад `postgresql://…?sslmode=require` |
| `SESSION_SECRET` | секрет підпису сесій, ≥ 32 символи |
| `JWT_SECRET` | секрет JWT, ≥ 32 символи |
| `APP_ORIGIN` | публічна адреса застосунку (на Render підхоплюється `RENDER_EXTERNAL_URL`) |
| `PORT` | порт (за замовчуванням 3000) |
| `NODE_ENV` | `production` на Render |

Локальна база не є частиною застосунку: код читає лише `DATABASE_URL`. Для розробки
можна вказати локальний PostgreSQL або окрему гілку Neon.

## Структура

```
src/
  controllers/studio/     огляд, опитування, конструктор, відповіді, категорії, люди, профіль
  controllers/api/        JWT API за ресурсами
  lib/validation/         правила валідації; lib/validation.js — тонкий реекспорт
  public/css/kolo.css     точка входу з @import; модулі в public/css/parts/
  public/js/app.js        точка входу; модулі поруч (core, selects, forms, builder, …)
  views/pages, partials   сторінки та винесені фрагменти
scripts/
  data/                   демо-дані: JSON-файли категорій, людей і опитувань
  lib/                    спільні хелпери для сіду
```

Кожен файл у `src/` і `scripts/` — не більше **200 рядків**. Це стосується CSS, JS,
Nunjucks, конфігурацій і демо-даних; виняток — `README.md` і згенерований
`package-lock.json`.

CSS не збирається бандлером: `kolo.css` лише імпортує частини. JS — нативні ES-модулі,
які підключає `app.js`.

## Ролі

| Роль | Що бачить |
| --- | --- |
| Гість | каталог і перегляд умов опитування; участь — після входу |
| Учасник | кабінет, проходження анкет, власні відповіді, профіль, каталог |
| Дослідник | власні опитування, конструктор, відповіді за своїми анкетами |
| Адміністратор | усі опитування, категорії, люди, копіювання анкет, повний API |

Публічна реєстрація створює лише роль «учасник». Дослідників та адміністраторів
додає адміністратор у розділі «Люди».

## REST API

Авторизація — `Authorization: Bearer <token>` після `POST /api/auth/login`.

```http
POST /api/auth/login      { "email": "...", "password": "..." }
GET  /api/auth/me
GET  /api/surveys
POST /api/surveys
GET  /api/surveys/:id
PUT  /api/surveys/:id
DELETE /api/surveys/:id
GET|POST|PUT|DELETE /api/categories
GET|POST|PUT|DELETE /api/users        (лише адміністратор)
GET|POST|PUT|DELETE /api/questions
GET|POST|PUT|DELETE /api/options
GET  /api/results                     (у межах ролі)
DELETE /api/results/:id
```

Відповіді на анкету надсилаються зі сторінки на `POST /surveys/:id/responses` із
CSRF-токеном; це сесійний, а не JWT-маршрут.

## Безпека

- bcrypt (12 раундів), паролі згенеровані `crypto.randomBytes` для сіду.
- CSRF-токен у сесії для всіх змінних запитів; JWT-маршрути захищені Bearer-токеном.
- Helmet із CSP, `httpOnly` + `SameSite=Lax` cookie, `secure` у production.
- Обмеження частоти входу та надсилання анкет.
- Валідація на сервері; HTML-атрибут `required` не використовується.
- Анонімні відповіді не прикріплюються до профілю для жодної ролі.

## Деплой на Render

`render.yaml` описує одразу базу й сервіс:

- Render Postgres `kolo-db` (Frankfurt, безкоштовний план) — тимчасова база до переходу на Neon;
- web service `kolo-survey-platform` (Node, free, Frankfurt);
- build: `npm ci --omit=dev && npm run db:setup` — створює схему й сідить порожню базу;
- start: `npm start`;
- health check: `/healthz`.

Після першого білду паролі демо-акаунтів друкуються в логах деплою; локальна копія
лежить у `credentials.production.md` (файл у `.gitignore`). Безкоштовний сервіс
засинає після простою, тому перший запит може тривати до хвилини.

### Перехід на Neon

1. Створіть проєкт у Neon і скопіюйте **direct** connection string із `?sslmode=require`.
2. У Render → Environment замініть `DATABASE_URL` на цей рядок і збережіть.
3. Новий деплой виконає `db:setup` уже на Neon; код змін не потребує.
4. Переконайтеся, що вхід і відповіді працюють, після чого видаліть Render Postgres.

Free Postgres на Render має обмежений термін життя, тому Neon лишається цільовою базою.
